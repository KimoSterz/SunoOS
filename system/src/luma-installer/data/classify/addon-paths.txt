# Device add-on paths (ADR-052 Amendment 1, section 2, "Classification",
# rules 4 and 5). Read by luma_installer/classify.py.
#
# A package whose own files (documentation, licences, translations and
# metadata aside) all lie under these paths is a device add-on, installed by
# the scope of its section; codecs, drivers and session add-ons may carry
# their own libraries and tools beside them (at most half of the files).
# TeX's fonts are not fonts here: they are TeX's data, in the workspace.
#
# [data]     data-only add-ons (icon, GTK and cursor themes, dictionaries,
#            sounds, wallpapers): for the person, under ~/.local/share,
#            after a file-type check
# [fonts]    font files: for the person, in ~/.local/share/fonts
# [codecs]   GStreamer and FFmpeg codecs: add-ons in that release's trees
#            and workspace
# [drivers]  scanner (SANE) backends: like codecs, add-ons in that release's
#            trees and workspace, loaded by the applications' libsane
# [application] "pattern application": plugin folders of one application that is not
#            Luma's own desktop (Thunar, Caja, Nemo, Dolphin): the package is that
#            application's add-on, added to its tree (kind application, add_on_of)
# [session]  native code loaded into the session (input-method engines,
#            Files and Shell extensions, portal backends). Toolkit modules
#            (GTK, GIO, pixbuf loaders, Qt platform plugins) are not: they load into
#            applications, which have their own trees, so a typed request for
#            one is a workspace package:
#            device-wide only as an image-signed system module after an
#            interactive yes, otherwise refused with the reason
#
# One fnmatch pattern per line, matched against absolute paths; "*" also
# matches "/". /usr/lib*/ covers the multiarch and lib64 directories.
